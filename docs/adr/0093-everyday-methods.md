# 0093. The everyday methods of the standard library (S2)

- Status: Accepted
- Date: 2026-11-12
- Refines: [ADR-0084](0084-a-complete-language-and-the-engine-apart.md) (Q542: record 4 of the
  audit of S2), docs/spec/02-types.md (lists and maps "are not compared with `==`"),
  docs/spec/08-closures.md (iterators) and docs/spec/07-errors.md (panics)

## Context

The audit of S2 ([`docs/std-audit.md`](../std-audit.md)) lists, for `String`, `StringBuilder`,
`char`, `List`, arrays, slices, `Map`, `Iter`, `Option` and `Result`, the methods of Rust's std
that most programs call and Sagitario lacks, and `assert`, `assert_eq`, `unreachable` and
`todo`. Tuples ([ADR-0092](0092-tuples.md)) let these methods have Rust's signatures where Rust
returns two values.

Some of Rust's forms do not fit Sagitario as they are: there are no macros, no overloading, no
lifetimes (a value cannot hold a borrow, so `entry` and `Peekable` cannot lend), ranges are not
values, slices are only the types of parameters, and `Iter<T>` is one class, where Rust tells
apart the iterators with two ends by a trait. This record keeps Rust's names and meanings and
says, for each such form, what stands for it.

## Decision

| # | Topic | Decision |
|---|---|---|
| Q617 | Names | The methods below have the names, arguments and meanings of Rust's, unless a row says otherwise. They are written in Sagitario, in the prelude, as the methods of lists already are (functions the compiler calls for a method of a built-in type); only what needs the compiler (Q626, Q627) is in it. |
| Q618 | Assertions | Prelude functions, as `panic`: `assert(condition: bool)`, `assert_eq<T: Eq>(left: T, right: T)`, `assert_ne<T: Eq>(left: T, right: T)`, `unreachable()` and `todo()`, the last two never returning, so they fit where any type is expected. A failure panics, in every build mode, at the file and line of the call: `assertion failed`, `assertion failed: left == right` with the debug form of both values on the next lines (`  left: 1`, ` right: 2`), `entered unreachable code`, `not yet implemented`. There is no message argument; a message is `if !condition { panic(f"...") }`. |
| Q619 | `Option` and `Result` | `ok_or`, `ok_or_else`, `or`, `or_else`, `and`, `xor`, `map_or`, `map_or_else`, `is_some_and`, `is_none_or`, `zip` (into a tuple), `flatten`, `iter`; on `Result`: `ok`, `err`, `and`, `or`, `or_else`, `map_or`, `is_ok_and`, `is_err_and`, `expect_err`, `iter`. `take` and `replace` change the place that holds the value, which an enum's method cannot: `mem::replace(&mut place, value)` and, with `Default`, `mem::take` (record 5) stand for them. `unwrap_or_default` waits for `Default`. `Option<T>` and `Result<T, E>` implement `Eq`, `Ord` and `Hash` when the types they hold do, as Rust's: the same variant holding equal values, ordered by variant as declared, then by those values, so `assert_eq(found, Some(2))` compiles. |
| Q620 | Strings | `rfind`, `split_whitespace`, `splitn(n, separator)`, `rsplit`, `split_once` and `rsplit_once` (giving `Option<(String, String)>`), `strip_prefix` and `strip_suffix` (`Option<String>`), `char_indices` (`(usize, char)` by byte index), `matches(pattern)` (the matches, as `split` gives a `List<String>`), `replacen(from, to, count)`, `to_uppercase` and `to_lowercase` (Unicode's full mappings, with the expansions `ß` to `SS`, and without a locale, as Rust's), and `String::from_utf8(bytes) -> Result<String, String>`, `String::from_utf8_lossy(bytes)` and `String::from_utf16(units) -> Result<String, String>`. `StringBuilder` gains `insert(index, text)`, `truncate(len)`, `pop() -> Option<char>`, `capacity()` and `reserve(n)`; an index inside a character panics, as Rust's. `char_count` is `chars().count()`, and padding is a format specifier (ADR-0089). |
| Q621 | Characters | `is_alphabetic`, `is_numeric`, `is_alphanumeric`, `is_whitespace`, `is_uppercase`, `is_lowercase`, `is_control`, `to_uppercase` and `to_lowercase` (a `String`, which holds the one to three characters Rust's iterator gives), `len_utf8`, `len_utf16`, and `char::from_digit(digit, radix) -> Option<char>`. The properties and mappings are those of Unicode 17, as Rust's `char` has them: tables in `compiler/std/unicode.sag`, generated by a program of `tools/` that prints them from Rust's `char` and is run by hand when Unicode changes, as `compiler/src/unicode.sag` was. |
| Q622 | Lists | `extend(values: Iter<T>)`, `append(other: List<T>)` (moving every element of `other`, which is left empty), `truncate`, `retain(keep)`, `dedup` (`T: Eq`), `swap(a, b)`, `split_off(at) -> List<T>`, `drain(start, end) -> List<T>` (indices, since ranges are not values), `binary_search(value) -> Result<usize, usize>` (`T: Ord`) and `binary_search_by(compare)`, `sort_by_key(key)` (`K: Ord`), `List::with_capacity(n)`, `reserve(n)`, `capacity()`, `windows(n)` and `chunks(n)` (an iterator of `List<T>`, copies, since slices are only parameters), `concat()` on a `List<List<T>>`, `fill(value)`, `min()` and `max()` (`T: Ord`, an `Option<T>`). `sort_unstable` is `sort`, which is already the fastest sort the library has. |
| Q623 | Equality of lists and maps | A list implements `Eq`, `Ord` and `Hash` when its elements do: `==` compares lengths and elements, and `<` orders by the first element that differs, as Rust's `Vec`. Arrays do the same. A map implements `Eq` when its values do: the same keys with equal values, in any order. This is a change of spec 2, which forbade `==` on lists and maps; on class instances `==` stays identity. A list used as a key of a map must not change while it is one, as in Rust, where a key cannot change. |
| Q624 | Arrays and slices | Arrays gain the methods of lists that keep their length: `contains`, `index_of`, `sort`, `sort_by`, `sort_by_key`, `reverse`, `fill`, `binary_search`, `min`, `max`, `swap`; those that change it need a `var` array, as other changes of a value. Slices gain `contains`, `index_of`, `binary_search`, `min`, `max`, and on `&mut [T]` `sort`, `sort_by`, `reverse`, `fill`, `swap` and `copy_from_slice(&[T])`. `split_at` is `&s[..i]` and `&s[i..]`. |
| Q625 | Maps | `entry` lends the map in Rust; closures stand for it: `update(key, f) -> bool` changes the value of a key that is present, `upsert(key, default, f)` inserts `default` or changes the value present with `f` (Rust's `entry(k).and_modify(f).or_insert(default)`), and `get_or_insert(key, value) -> V` gives the value present or inserts `value`. Also `retain(keep: fn(K, V) -> bool)`, `extend(pairs: Iter<(K, V)>)`, `Map::from(pairs: List<(K, V)>)` and `iter() -> Iter<(K, V)>`. |
| Q626 | Iterators | Adapters: `enumerate` (`(usize, T)`), `zip` (`(T, U)`), `chain`, `flat_map`, `flatten` (of iterators, lists and options), `take_while`, `skip_while`, `map_while`, `inspect`, `cycle` (which keeps the values it has given, as Rust's clones the iterator). Consumers: `sum` and `product` (of integers and floats; `0` and `1` when empty), `min`, `max` (`T: Ord`), `min_by`, `max_by`, `min_by_key`, `max_by_key`, `position`, `last`, `nth`, `partition` (`(List<T>, List<T>)`), `unzip` (of an iterator of pairs, `(List<A>, List<B>)`). Every iterator has `peek() -> Option<T>`, which keeps the value for the next `next()`: Rust's `Peekable` lends its iterator, which Sagitario cannot, so `peekable()` is not needed. `scan` needs a state a closure changes; it waits for closures that can assign their captures. |
| Q627 | Two ends | As Rust's `DoubleEndedIterator`, iterators that can also give their last value are of a prelude class `DoubleEndedIter<T>`, which extends `Iter<T>` and adds `next_back()` and `rev()`; `rev()` on any other iterator is an error, with a note to collect into a list and call `reverse`. `list.iter()`, the iterators of arrays and slices, ranges, `chars()`, `bytes()` and `char_indices()` give one, and `map`, `filter`, `inspect`, `chain` (of two) and `rev` keep both ends, which the compiler gives that class as it gives lists their methods. The other adapters give an `Iter<T>`. Rust also keeps both ends through `enumerate`, `zip`, `take` and `skip` of iterators that know their length; that waits for a record on lengths (`ExactSizeIterator`). `(a..b).rev()` in `for` stays the loop it is today. |
| Q628 | `collect` | `collect()` makes the type the context expects, as Rust's: a `List<T>` without one, a `Map<K, V>` from an iterator of `(K, V)`, a `String` from an iterator of `char` or of `String`, and a `Result<List<T>, E>` from an iterator of `Result<T, E>`, which stops at the first `Err`. There is no `FromIterator` interface yet; other types are an error. |
| Q629 | The editor | Every new method is completed by `sag lsp` on its type with its signature, and the editor's README lists the families; `assert` and `assert_eq` get snippets. |
| Q630 | Increments | **1** Assertions, `Option` and `Result` (Q618, Q619). **2** Strings, `StringBuilder` and characters, with the Unicode tables (Q620, Q621). **3** Lists, arrays and slices, and the equality of lists and maps (Q622–Q624). **4** Maps (Q625). **5** Iterators, `DoubleEndedIter` and `collect` (Q626–Q628). Each one with its tests, the spec and the editor, and the rows of the audit marked. |

### Example

```sag
fn main() {
  const text = "key=value";
  const (key, value) = text.split_once("=").unwrap();
  const counts = new Map<String, i32>();

  for word in "a b a".split_whitespace() {
    counts.upsert(word, 1, (n) => n + 1);
  }

  const evens: List<i32> = (1..=10).filter((n) => n % 2 == 0).rev().collect();
  const total: i32 = evens.iter().sum();

  assert_eq(counts.get("a"), Some(2));
  assert_eq(List::from([10, 8, 6, 4, 2]), evens);
  println(f"{key} {value} {total} {'ß'.to_uppercase()}");   // key value 30 SS
}
```

## Alternatives considered

- **`collect_map()` and `collect_string()`:** no inference from the context, but a name per
  target where Rust has one; the expected type already chooses among the instantiations of
  generic functions.
- **`==` on lists only through `equals`:** it would keep `==` identity-like for all references,
  but Rust compares vectors by value, and a list is a value to most programs.
- **An `Entry` class:** Rust's API, but each call would allocate an object holding the map and
  the key, to do what one method with a closure does.
- **`rev()` on any iterator, collecting when it has no back end:** it never fails, but hides an
  allocation and a pass over every value, which Rust makes visible as an error.
- **Ranges as values first:** `drain(a..b)` would read as Rust's, but ranges as values are a
  change of the language of their own; indices say the same today.

## Consequences

- Programs written against Rust's std find most of its everyday methods, with the same names.
- The prelude grows; the Unicode tables are the largest part, and only the programs calling
  their methods have them in their C.
- `list.iter()` and the other iterators with two ends have a new type, `DoubleEndedIter<T>`,
  which is an `Iter<T>` wherever one is expected, so programs written for `Iter<T>` still work.
- The equality of lists and maps changes spec 2; code that compared lists by identity through
  `==` could not be written before, so nothing changes meaning.

## Notes

- Increment 1 is done. The assertions are builtins, as `panic` is, so that SIR panics at the
  line of the call, the way Rust's `#[track_caller]` does: `assert` tests its condition,
  `unreachable` and `todo` panic, and `assert_eq` and `assert_ne` call the generic prelude
  functions `assert_eq_failure` and `assert_ne_failure`, which check `Eq` and give the message
  with the debug form of both values, or `None`. A function of a program with one of these names
  takes their place, as for `panic`. The new methods of `Option` and `Result` are prelude
  functions (`option_ok_or`, `result_ok`...); `types::collections::inferred_prelude_method`
  takes their type parameters from the receiver, then infers the others from the arguments, as
  a generic call does. `expect_err` is a builtin beside `expect`, to panic at the call's line.
  Writing the test of `assert_eq` showed that `Option` and `Result` did not implement `Eq`, which
  Rust's do and which `assert_eq(found, Some(2))` needs: they now implement `Eq`, `Ord` and
  `Hash` as tuples do, in `sir/collections.sag`, by variant and then by the value held.
- Increment 2 is done. The methods of `String`, `char` and `StringBuilder` are functions of the
  root of `std` (`text_<name>`, `char_<name>`), not of the prelude, since they need the Unicode
  data and the UTF-8 helpers the root already had; `types::collections::std_root_fn` finds them.
  The data is a module `std::unicode`, hidden from programs as `std::sys` is, which the root
  loads: `tools/unicode.rs`, run with `rustc`, prints it from Rust's `char` (Unicode 17.0.0)
  after checking every code point against it, and appends the search written in
  `tools/unicode_search.sag`, which a test of the harness keeps in step. Each table is a string
  constant of numbers of six hexadecimal digits, searched without being decoded first, so a
  program pays nothing before its first lookup and nothing at all if it makes none: ranges for
  the properties, and for each case mapping runs `start, end, step, offset` (198 for uppercase,
  185 for lowercase) plus the characters mapped to several (102 and 1). `to_lowercase` of a `String` gives `ς` for a `Σ` with a
  cased character before it and none after it; Rust also skips the case-ignorable characters
  around it, which the tables do not have. `insert`, `truncate`, `pop`, `capacity` and `reserve`
  of `StringBuilder` are runtime functions, since they reach its buffer.
